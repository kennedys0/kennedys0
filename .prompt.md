### 9. SIGNATURE FEATURE — CHALLENGE ME

This must be the most distinctive interaction in the portfolio.

Build a dedicated page at `/challenge-me`.

Use two primary modes:

**MODE A — SEND ME A CHALLENGE**

Let visitors submit legitimate and authorized security research invitations.

Purpose:
Allow organizations, developers, and security teams to invite FEKOJEWAN to assess a website, API, or authorized laboratory environment.

Headline:

"Got a Security Challenge?"

Supporting copy:

"Have a web application, API, or security puzzle worth investigating? Send me a challenge and let's see what breaks — responsibly."

Form fields:
- Name
- Contact email
- Company / Organization (optional)
- Challenge title
- Challenge category
- Target type (Web Application / REST API / GraphQL API / Other)
- Target URL (optional)
- Authorized scope description
- Rules of engagement
- Challenge description
- Deadline (optional)
- Public or Private request
- Authorization confirmation checkbox

Authorization checkbox:

"I confirm that I own this system or have explicit authority to invite security testing within the stated scope."

Additional security requirements:
- Validate all fields on the server.
- Enforce submission rate limits.
- Use bot protection.
- Reject dangerous URL schemes and malformed values.
- Do not automatically scan or access submitted target URLs.
- Do not trigger any security testing automatically.
- Do not solicit passwords, tokens, session cookies, or production secrets.
- Store submissions privately.
- Require manual review before acceptance.
- Provide a clear privacy notice.
- Prevent user-submitted content from becoming executable HTML.
- Do not expose private target information on public pages.

Submission flow:
1. Visitor completes the form.
2. Server validates the request.
3. Submission receives a unique identifier.
4. Store it with Pending Review status.
5. Notify the owner via configured email.
6. Show a successful submission state.
7. Let the owner review, accept, decline, or request clarification.

Suggested statuses:
- Pending Review
- Needs Clarification
- Accepted
- In Progress
- Completed
- Declined

Only authenticated owner users may change statuses.

Never publicly publish challenge information without explicit permission.

**MODE B — SECURITY CHALLENGE ARENA**

Create a second mode where visitors can test their own skills.

This should be a self-contained, authorized training environment.

Headline:

"Think Like a Hunter."

Subtitle:

"Solve small web and API security puzzles and test your reasoning."

Create three starter challenges:

**Challenge 01 — Broken Access Control**
- Difficulty: Easy
- Topic: API authorization
- Players inspect synthetic request/response data.
- They must identify an authorization flaw.
- Provide hints and explanations.

**Challenge 02 — JWT Security**
- Difficulty: Medium
- Topic: Token validation
- Players identify an intentionally flawed verification assumption in a fictional system.
- Use synthetic tokens and fictional data.

**Challenge 03 — Business Logic**
- Difficulty: Hard
- Topic: Workflow validation
- Players inspect a simulated sequence of API requests and identify the broken security invariant.
- The entire exercise must operate within fictional, self-contained data.

Challenge UI:
- Difficulty badge
- Category
- Estimated completion time
- Scenario description
- Fake API request viewer
- Fake API response viewer
- Response analysis panel
- Hints
- Answer submission
- Result feedback
- Explanation after solving
- Progress indicator
- Score

Scoring:
- Easy: 100 points
- Medium: 250 points
- Hard: 500 points
- Hint usage reduces awarded points according to a documented rule
- Optional completion time for personal feedback, not mandatory ranking

Security architecture:
- Keep solutions and validation rules on the server.
- Never include answer keys in client bundles.
- Apply rate limits to answer attempts.
- Do not provide a proxy to arbitrary external targets.
- Do not execute submitted code.
- Keep all simulations inside isolated application logic.
- Never expose production services as challenge targets.

Optional:
- Anonymous local progress
- Account-based progress if authentication is introduced
- Privacy-conscious leaderboard with user-selected public nicknames
- Achievement badges
- Accessible success animations

The Challenge Arena must be educational, interactive, and genuinely functional.

It must not be a collection of decorative cards with non-working buttons.
